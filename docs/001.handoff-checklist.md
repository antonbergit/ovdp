# 001 Handoff Checklist

## Audit

- Раньше в серии был логический разрыв: правило в `006` требовало старт с `001`, но первый фактический артефакт начинался с `002`.
- Этот файл закрывает разрыв и делает последовательность читаемой с самого начала.
- Теперь handoff можно восстанавливать без догадок: `001` -> `002` -> `003` ... `011`.

## Current Project Frame

- Цель: долгосрочные инвестиции в украинские ОВДП на основе прозрачных данных и зафиксированных правил.
- Источник данных: `https://next.privat24.ua/bonds/list`.
- Рабочий принцип: извлекать все возможные данные, хранить сырой слой отдельно от нормализованного и исторического.
- Формат: все артефакты именуются по маске `NNN.artefact_name.md`.

## What Already Exists

- Зафиксированы цели, допущения, источник данных, правила, workflow и журнал решений.
- Проведён эксперимент по структуре `bonds` данных, но реальный payload ещё не извлечён.
- Проведена серия экспериментов по session bootstrap:
  - `API_INITIAL` работает через `POST`;
  - `pubkey` и `xref` доступны;
  - `redirect` указывает на необходимость отдельного `sid`;
  - `createSession` уходит в `POST /api/p24/init?dyn_string=...`;
  - без валидного `dyn_string` и `sid` доступ к `bonds` не раскрывается.

## Handoff Checklist

- Сначала прочитать `002` и `006`, чтобы восстановить правила и карту документов.
- Затем читать `010` и `011`, потому что это текущая исследовательская база.
- Проверять новые выводы только через отдельные экспериментальные записи.
- Все значимые развилки сразу писать в `008.decisions.md`.
- Если меняется структура источника, обновлять `010`, `011` и индекс в `002`.

## Open Gaps

- Нет валидного `sid`.
- Нет валидного `dyn_string` для рабочей session bridge цепочки.
- Нет реального `bonds` JSON payload.

## Next Step

Добрать рабочую session bridge цепочку, затем снять один живой `bonds` payload и зафиксировать нормализованную схему хранения.
