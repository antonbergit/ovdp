# 013 Experimental Runbook

## Purpose

Короткий рабочий маршрут для следующего цикла экспериментов по Privat24 bonds.

Этот документ нужен не для фиксации истории, а для того, чтобы следующий заход можно было начать быстро и одинаково.

## Primary Goal

Добраться до рабочей session bridge цепочки и снять один живой `bonds` payload.

## Working Assumptions

- `API_INITIAL` уже подтверждён как минимальный стартовый вход.
- `pubkey` и `xref` доступны после успешного `API_INITIAL`.
- `sid` пока не найден.
- `dyn_string` пока не найден в валидной форме.
- для auth-bridge нужен точный `X-Request-origin: https://next.privat24.ua`;
- `GET /http?phone=...` создаёт одноразовый queued state через `defaultPageToken_*`.

## Recommended Run Order

1. Проверить, не изменился ли HTML/JS flow на `https://next.privat24.ua/bonds/list`.
2. Сверить текущие наблюдения с [011.session-bootstrap-experiments.md](011.session-bootstrap-experiments.md).
3. Снять свежий `/http` bridge через `X-Request-origin` и `phone=380...`, сразу прочитать следующий `GET /http` и сохранить cookie jar.
4. Снять свежий `API_INITIAL` и сохранить сырой ответ и cookie jar.
5. Проверить `redirect` и `createSession` ветки отдельно.
6. Искать source of truth для `sid` и `dyn_string` в сетевом следе браузера.
7. Повторить полный цикл только после появления валидного мостика.

## Success Criteria

- найден валидный `sid` или доказано, что он создаётся в другом шаге;
- найден валидный `dyn_string`, который проходит `createSession`;
- `bonds` API возвращает не ошибку, а живой JSON payload;
- payload описан в [010.bonds-data-structure.md](010.bonds-data-structure.md);
- новые выводы записаны в [008.decisions.md](008.decisions.md).
- `show_ivr_form`/`show_sms_form` queued state подтверждён и зафиксирован в [014.auth-bridge-minimum-flow.md](014.auth-bridge-minimum-flow.md).

## What To Record

- точный request path;
- method;
- request headers;
- query params;
- body;
- response code;
- response body;
- cookies touched;
- interpretation.

## Stop Conditions

- Если шаг не даёт новых признаков, фиксируем это как отдельный отрицательный результат.
- Если эксперимент начинает повторять уже известный отказ, не расширяем его бесконечно.
- Если появляется новый артефакт, сразу обновляем соответствующий документ и индекс.
